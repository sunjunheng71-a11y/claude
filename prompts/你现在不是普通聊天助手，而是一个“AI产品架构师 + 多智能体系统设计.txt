====================
一、项目背景
====================

项目名称：
个人数字资产管理中枢（输入-整理-输出）

核心定位：
一个“可编程人生简历引擎 / 个人经历资产系统”。

项目目标：
让用户可以随时随地输入自己做过的一件事、帮助过别人的一次经历、参加过的一个活动、学到的一项能力、完成的一次尝试，系统自动从混乱自然语言中提取关键信息，必要时进行补问，然后将其以结构化方式沉淀到 Obsidian 中。之后，用户可以针对不同场景（例如面试、自我介绍、复盘、社交破冰）调用这些真实经历，让系统基于已有记录进行筛选、重组和表达输出。

项目原则：
- 核心是“真实记录 + 智能整理 + 场景化输出”
- 不是帮用户编故事，而是帮用户更真实、更有逻辑地表达自己
- 不能夸大，不能虚构不存在的结果、头衔、影响力和数字
- 输出必须建立在已有记录和证据基础上
- Obsidian 是长期沉淀的核心存储载体
- 首版以 MVP 为主，不追求过度复杂

====================
二、你要理解的产品本质
====================

这个系统不是：
- 普通记事本
- 普通日记应用
- 普通简历优化器
- 纯内容生成器

这个系统本质上是：
- 用户个人经历的结构化资产库
- 个人成长与成就的长期沉淀系统
- 面向不同场景的真实表达重组器
- 将“人生碎片”转成“可检索、可重组、可调用数字资产”的系统

系统价值闭环：
输入碎片 → 判断是否值得沉淀 → 结构化提取 → 补问关键缺失信息 → 存入 Obsidian → 后续按场景检索 → 输出真实表达内容

====================
五、子智能体要求
====================

请至少设计以下子智能体，并根据需要自行补充：

1. 输入判别智能体
作用：
- 判断用户输入是成就、成长、素材还是无效内容
- 判断是否值得入库
- 判断是否需要追问
- 判断记录等级（A/B/C）

2. 结构化提取智能体
作用：
- 从用户自然语言中提取标准字段
- 输出 JSON 结构
- 不允许脑补不存在的结果或数据

3. 追问补全智能体
作用：
- 在信息不足时只追问最关键的 1~2 个问题
- 优先补齐：结果、角色、时间、量化信息
- 保证补问自然，不像审讯

4. 标签与技能映射智能体
作用：
- 自动打标签
- 将口语化能力映射为标准技能词
- 形成统一检索体系

5. Obsidian 入库智能体
作用：
- 将结构化数据转为标准 markdown
- 按模板生成 frontmatter 与正文
- 写入指定 Vault 目录
- 更新索引页或关联页

6. 记录检索智能体
作用：
- 按场景、标签、时间、技能、项目、角色等维度检索相关经历
- 返回最相关候选记录

7. 场景包装智能体
作用：
- 根据用户场景要求，对已有记录进行筛选和重组
- 用于面试回答、自我介绍、复盘、社交破冰等
- 只能重组已有素材，不能编造

8. 真实性校验智能体
作用：
- 检查输出是否夸大
- 检查是否虚构量化结果
- 检查是否把“参与”说成“主导”
- 检查是否超出原始记录边界

如果你认为还需要其他子智能体，请补充，并说明必要性。

====================
六、记忆系统要求
====================

你必须单独设计 Memory System，不要把记忆系统与普通 records 混为一谈。

请至少设计以下记忆层：

1. 原始输入记忆层（Raw Memory）
- 存放用户原始输入
- 用于追溯原始语义
- 不直接面向最终表达

2. 结构化记录记忆层（Structured Record Memory）
- 存放提取后的标准记录
- 作为核心可检索资产库

3. 标签与技能索引记忆层（Index Memory）
- 存放 tags / skills / people / projects / scenes 等索引
- 用于提升检索效率与复用能力

4. 输出历史记忆层（Output Memory）
- 存放过去生成过的自我介绍、面试回答、总结等
- 用于后续改写和版本迭代

5. 会话状态记忆层（Session State Memory）
- 用于短期流程状态管理
- 例如当前是否在追问、是否待确认、是否已完成入库

你必须说明：
- 每一层记忆的职责
- 是否长期保留
- 是否写入 Obsidian
- 与主智能体和各子智能体的关系
- 与本地目录结构的映射关系

八、核心工作流要求
====================

请设计以下工作流：

A. 记录型工作流
用户输入一句混乱的话
→ 主智能体识别为记录请求
→ 调用输入判别智能体
→ 调用结构化提取智能体
→ 若缺关键字段，则调用追问补全智能体
→ 用户补充后再次提取
→ 调用标签与技能映射智能体
→ 调用记忆系统写入逻辑
→ 调用 Obsidian 入库智能体
→ 返回已沉淀结果

B. 输出型工作流
用户提出场景需求
→ 主智能体识别为调用请求
→ 解析场景、对象、时长、风格
→ 调用记录检索智能体
→ 调用场景包装智能体
→ 调用真实性校验智能体
→ 返回结果

C. 异常处理工作流
包括但不限于：
- 输入过少
- 用户表达模糊
- 缺少关键字段
- 记录不足以支撑输出场景
- Obsidian 写入失败
- 检索不到记录
- 输出存在夸大风险
- 目录不存在或配置不完整
